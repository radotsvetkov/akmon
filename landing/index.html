AkmonAKMON

Prove what your AI agent did, to someone who doesn't trust you.

Months or years from now, an auditor, a customer or a regulator will ask what the agent actually did. Your logs won't settle it, because you wrote them and you can still change them. Akmon seals the session into one signed, tamper-evident file. They verify it on their own machine, offline, with a small standalone verifier or with plain OpenSSL. They don't need Akmon, a cloud service or your word.

any OpenTelemetry agent one sealed file Ed25519 signed offline verify honest capture level Apache-2.0

// how it works

Seal. Hand over.
They verify.

Three steps. Only the first one needs Akmon.

01

Seal the session

Give akmon seal an OpenTelemetry GenAI trace from any agent, or a session from Akmon's reference agent. It imports the session, bundles it, checks integrity, signs it with your Ed25519 key and verifies its own output.

akmon bundle keygen --out signer.pk8 \
  --public-out signer.pub
akmon seal trace.json --key signer.pk8 \
  --output audit.akmon
02

Hand over one file

Send audit.akmon however you like. Send the public key over a separate, trusted channel: the .pub file is a convenience copy to send that way, and the auditor verifies with the key they received out-of-band, never one that travelled with the bundle. Add --operator-key to record a signed sign-off by an accountable person, and --proof-dir for OpenSSL artifacts.

audit.akmon       # the evidence
audit.akmon.pub   # signer public key (hex), send separately
03

They verify, offline

The auditor runs the small agef-verify binary and gets a verdict, or a Markdown report for the file. With no Akmon at all, stock OpenSSL 3 checks the signature.

agef-verify audit.akmon --verify-key signer.pub \
  --require-signature --format markdown > report.md
openssl pkeyutl -verify -pubin -inkey proof/pubkey.pem \
  -rawin -in proof/statement.bin -sigfile proof/signature.bin
// no overclaiming

What a pass proves,
and what it doesn't

Evidence is only useful if its limits are stated. The verifier's Markdown report prints both lists.

Proves

  • Integrity. Every event and content object hashes into the session head. Nothing was changed, added, removed or reordered since then.
  • Who signed. The holder of the trusted Ed25519 key signed that exact head, under the domain-separated AGEF-SIG-v1 statement.
  • Operator sign-off (optional). A second key signed an AGEF-OPERATOR-v1 attestation naming an accountable person and role.
  • Capture honesty. Whether the record is full, partial or structural is part of the signed record. An imported trace is labelled full only when every content slot is real; otherwise it is partial or structural, and it is never replayable.

Does not prove

  • When. Event times come from the producer's clock, and AGEF signatures don't cover a trusted time yet. Until native support lands, there's an interim RFC 3161 recipe using stock OpenSSL.
  • Whose key it is. Binding a key to a person or organization is your out-of-band step.
  • That the operator's name is true. Names and roles are self-asserted, and only the key is verified.
  • That the agent was right, or that any obligation was met. This is evidence, not a verdict on behaviour.
// eu ai act · as of 1 nov 2026

Deferred,
not cancelled

Regulation (EU) 2024/1689, as amended by the Digital Omnibus on AI, Regulation (EU) 2026/1744 (in force 27 July 2026). Akmon helps you produce evidence. It does not make a system compliant.

  1. FEB 2025Prohibitions and AI literacy apply.
  2. AUG 2025General-purpose AI model obligations and the penalties regime apply. Commission enforcement powers from 2 Aug 2026.
  3. 2 AUG 2026Art. 50 transparency applies. Machine-readable marking has a grace period to 2 Dec 2026 for systems already on the market.
  4. 2 DEC 2027High-risk, Annex III: Art. 12 automatic logging; Art. 19 and 26(6), providers and deployers keep logs for at least 6 months.
  5. 2 AUG 2028High-risk, Annex I (AI embedded in regulated products): the same Chapter III duties.

Where a sealed bundle fits: tamper-evident session logs for Art. 12-style record-keeping, kept under your own retention policy. It also fits Annex IV point 2(g), "test logs and all test reports dated and signed by the responsible persons": a signed test session plus an operator attestation, with a trusted timestamp added for the "dated" part. And it fits Art. 73 incident reporting, where a bundle sealed at the time, plus an RFC 3161 timestamp taken at the time, helps show the records were preserved. A signature alone does not prove when a bundle was sealed.

What it doesn't do: an operator attestation helps you evidence human oversight. It does not by itself satisfy Art. 14. The Art. 12(3) minimum fields apply only to remote biometric identification. No harmonised logging standard (ISO/IEC 24970, prEN 18229-1) gives a presumption of conformity yet.

Already in force elsewhere: DORA's tamper-protected ICT logs, NIS2 logging requirements (Implementing Regulation 2024/2690 for the digital-infrastructure and ICT-service entity types it covers), and Cyber Resilience Act incident reporting (since 11 Sep 2026).

Not legal advice. Check the mapping with your own counsel. Details and sources are on the compliance page.

Install

Two binaries: akmon to seal, and agef-verify, which is all an auditor needs. Each release ships prebuilt binaries for macOS and Linux with SHA256SUMS and a CycloneDX SBOM. Check the checksums before you install.

# macOS or Linux
brew tap radotsvetkov/akmon
brew install akmon agef-verify
akmon --version # akmon 3.0.0
# the tap is updated by hand, so it may lag a new release briefly
# openssl proofs need OpenSSL 3.x (macOS ships LibreSSL): brew install openssl@3
# Apple silicon, installs to ~/bin (no sudo)
cd "$(mktemp -d)"
base=https://github.com/radotsvetkov/akmon/releases/latest/download
curl -fL -O "$base/akmon-darwin-arm64" -O "$base/agef-verify-darwin-arm64" -O "$base/SHA256SUMS"
shasum -a 256 --check --ignore-missing SHA256SUMS # both lines must say OK
chmod +x akmon-darwin-arm64 agef-verify-darwin-arm64
mkdir -p ~/bin && mv akmon-darwin-arm64 ~/bin/akmon && mv agef-verify-darwin-arm64 ~/bin/agef-verify
# not found? add ~/bin to PATH: echo 'export PATH="$HOME/bin:$PATH"' >> ~/.zshrc
# Intel Mac, installs to ~/bin (no sudo)
cd "$(mktemp -d)"
base=https://github.com/radotsvetkov/akmon/releases/latest/download
curl -fL -O "$base/akmon-darwin-x86_64" -O "$base/agef-verify-darwin-x86_64" -O "$base/SHA256SUMS"
shasum -a 256 --check --ignore-missing SHA256SUMS
chmod +x akmon-darwin-x86_64 agef-verify-darwin-x86_64
mkdir -p ~/bin && mv akmon-darwin-x86_64 ~/bin/akmon && mv agef-verify-darwin-x86_64 ~/bin/agef-verify
# Linux x86_64 (glibc), installs to ~/bin
cd "$(mktemp -d)"
base=https://github.com/radotsvetkov/akmon/releases/latest/download
curl -fL -O "$base/akmon-linux-x86_64" -O "$base/agef-verify-linux-x86_64" -O "$base/SHA256SUMS"
sha256sum --check --ignore-missing SHA256SUMS
chmod +x akmon-linux-x86_64 agef-verify-linux-x86_64
mkdir -p ~/bin && mv akmon-linux-x86_64 ~/bin/akmon && mv agef-verify-linux-x86_64 ~/bin/agef-verify
# Rust 1.88+. The CLI package is akmon-cli; it installs the `akmon` binary.
cargo install --locked --git https://github.com/radotsvetkov/akmon akmon-cli
cargo install --locked --git https://github.com/radotsvetkov/akmon agef-verify

A reference agent
and an open format

Akmon ships a terminal agent (akmon chat, akmon --task "…") with permission gates, a sandbox and a policy engine. It has one job: to be the full-capture reference producer, recording sessions completely enough for akmon replay and akmon diff. You don't need it to seal another agent's sessions.

Bundles follow the open AGEF specification (v0.1.3): content-addressed objects, a hash-linked event chain, optional Ed25519 signatures and operator attestations. The format is documented, so you can write your own verifier, and nothing ties you to Akmon.
